---
name: paper-view-canvas
description: Draw and revise editable SVG diagrams progressively on Paper View Board, or generate raster images.
---

For editable PPTX, avoid `gradientTransform`: production testing confirmed that a transformed gradient uploads but fails selected-element PowerPoint export. Set gradient coordinates directly and verify the downloaded slide.

Connect through the Paper View website OAuth page at `https://ipaperview.com` before calling paid tools. Use `list_image_models` to check model and image-size support. Use `quote_image` to report the current Credit cost before a requested generation. Submit with `submit_image`, retaining the returned `job_id` and a stable `client_request_id` for retries. Pass the returned `session_id` on each follow-up change to keep results on the same canvas; omit it only for a new canvas. Use `list_image_jobs` to recover a lost session ID. Poll `get_image_job` until completed or failed. Open the first completed job's `board_url` in WorkBuddy's browser panel if available, or provide a clickable link. Use `open_canvas` only to recover a session's compact board URL. For follow-up jobs, keep the same panel open and let the canvas refresh automatically; do not reopen the URL. The generated raster image can be arranged with SVG elements in the board; do not claim the image pixels are vectors. Never place tokens in tool arguments or chat text.

For one vector figure that should download and edit as a whole, call `start_drawing` once and `draw_svg_layer` once for its first stage. Retain the returned `session_id` and `artifact_ref`. For every later stage, call `get_svg_layer`, then `update_svg_layer` on that same ref with the latest `revision` as `base_revision` and the **complete cumulative SVG**, keeping earlier content plus the new section. The interface replaces the document; it does not append or merge SVG fragments. Keep a fixed numeric `viewBox`, pass SVG text rather than a local file path, and use a stable UUID `client_request_id` per new submission; reuse it only for retries of the exact request.

Every additional `draw_svg_layer` creates an independent board object, even with the same canvas and `viewBox`. Add objects only for separate figures, explicitly requested separate layers, or size-limit splits. Do not describe these objects as one selectable/downloadable figure without combining and verifying them. `inspect_drawing` lists objects and revisions; one progressively drawn figure should have one ref with increasing revisions. Open the canvas once and let it synchronize. After the final stage, verify the whole figure can be selected, its SVG download contains all sections, and one click on Edit exposes their independent elements. On a revision conflict or Board-local user edits, inspect and preserve those changes instead of forcing replacement; the saved agent source is not proof that local edits were merged.

SVG objects may use shapes, paths, groups, text, local gradients and start/end markers with direct presentation attributes. The MCP rejects `clip-path`, `mask`, `pattern`, `symbol/use`, `filter`, `style/class`, `image`, `foreignObject`, animation, external resources, and `tspan dx/dy`; redraw these with concrete shapes, direct geometry, explicit `x/y` text positions, or a separate raster image when vector reconstruction is unsuitable. Although `marker-mid` uploads, it prevents editable PPTX conversion, so use explicit polygons for intermediate arrowheads. Each complete object is limited to 512 KiB and 4,000 elements at every revision. Verify selected-element PPTX download when editability matters; whole-board PPTX is a picture. SVG tools do not consume image-generation Credits.
